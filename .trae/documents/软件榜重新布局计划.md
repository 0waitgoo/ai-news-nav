# 软件榜重新布局计划

## 目标
重新设计软件榜的展示布局，增加用户评分/口碑和热度/使用量数据的可信度。

## 需求分析

### 1. 用户评分/口碑展示
- 采用五星制或10分制评分
- 显示评价人数（如 4.8分 / 1.2万评价）
- 参考TopAI.tools、Toolify的模式

### 2. 热度/使用量数据优化
- 保留现有的"1.8亿"类数字
- 统一单位（月活用户数 / 累计使用次数）
- 标注统计周期（如"2026年2月数据"）

## 实施步骤

### 步骤1: 更新数据结构
**文件**: `api/index.js`
- 修改 `softwareRankingData` 数组
- 为每个软件添加字段：
  - `rating`: 评分（如 4.8）
  - `ratingScale`: 评分制度（5分制或10分制）
  - `reviewCount`: 评价人数（如 "1.2万"）
  - `usageMetric`: 使用量指标类型（"月活用户" / "周访问量" / "累计使用"）
  - `usageValue`: 使用量数值（如 "1.8亿"）
  - `dataPeriod`: 数据统计周期（如 "2026年2月"）

### 步骤2: 更新前端展示组件
**文件**: `src/components/widgets/NewsWidget.tsx`
- 修改软件榜的渲染逻辑
- 新的布局设计：
  ```
  [排名] [软件名称] [评分 ★★★★★ 4.8/5 · 1.2万评价]
         [描述]
         [🔥 月活用户 1.8亿 · 2026年2月数据]
  ```
- 添加评分星星可视化组件
- 调整样式以适应新布局

### 步骤3: 更新类型定义
**文件**: `src/services/api.ts`
- 更新 `SoftwareRankingItem` 接口
- 添加新的字段类型定义
- 更新备用数据以匹配新结构

### 步骤4: 数据收集与填充
- 为每个软件收集真实的评分和评价数据
- 确定统一的使用量指标（建议统一使用"月活用户"）
- 标注数据来源和统计周期

## 技术实现要点

1. **评分星星组件**
   - 根据rating和ratingScale计算填充星星数量
   - 支持半星显示
   - 使用黄色/金色配色

2. **数据格式化**
   - 评价人数统一格式化（如125000 → "12.5万"）
   - 使用量数值统一格式化

3. **响应式布局**
   - 确保在移动端也能良好展示
   - 考虑文字过长时的截断处理
